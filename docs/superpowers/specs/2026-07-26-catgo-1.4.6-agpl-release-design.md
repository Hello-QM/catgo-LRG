# CatGo 1.4.6 AGPL Release Design

**Date:** 2026-07-26  
**Status:** Approved direction; implementation pending

## Context

CatGo 1.4.6 is prepared on `feat/noncommercial-license`, but the branch
currently replaces the project's AGPL declaration with a custom
noncommercial license. Historical contributions have no complete written
relicensing record, so that license change cannot be applied safely to the
whole existing codebase.

The branch also introduced a fail-closed release pipeline, an all-platform
Cloudflare download hub, Cloudflare-hosted automatic updates, exact release
source and artifact verification, and extensive third-party notice retention.
Those improvements are independent of the custom license and should be kept.

Two machine-readable release gates remain unresolved:

- the bundled PORMAKE database contains RCSR and ToBaCCo material without
  established redistribution authority; and
- the pymatgen/ASE/xterm provenance ledger records incomplete adopted-revision
  history, including four ASE-derived tests.

The release must not bypass these gates by changing an unknown or blocked
status to cleared without a concrete technical basis.

## Decision

CatGo 1.4.6 will remain licensed under `AGPL-3.0-or-later`.

The custom CatGo Noncommercial Research License and commercial-license offer
will be removed from active release surfaces. Acknowledgement and citation
will remain prominently requested and machine-readable through `CITATION.cff`,
but they will not be represented as additional AGPL conditions.

The v1.4.6 release will exclude material whose redistribution authority has
not been established. This trades the bundled reticular builder for a
releaseable, internally consistent distribution.

## Considered Approaches

### 1. AGPL release with verified exclusion — selected

Restore AGPL everywhere, preserve the hardened release and Cloudflare work,
remove the uncleared bundled database and affected feature entrypoints, and
replace or remove the small ASE-derived test scope.

This is the only approach that both avoids a whole-project relicense and
allows the release-rights gate to pass without inventing evidence.

### 2. Keep the custom noncommercial license and wait

Leave the current draft unchanged until every contributor and external
rightsholder supplies written authority.

This preserves the intended commercial restriction but does not satisfy the
near-term v1.4.6 release goal.

### 3. AGPL release while retaining the unresolved database

Restore AGPL but continue bundling the PORMAKE/RCSR/ToBaCCo database.

AGPL does not grant redistribution rights for separately sourced data. This
approach leaves the known blocker in every source and binary artifact and is
therefore rejected.

## License Surfaces

The implementation will restore the canonical GNU Affero General Public
License version 3 text and `AGPL-3.0-or-later` metadata across:

- the repository root;
- npm and workspace packages;
- Rust crates;
- the Python server and extension packages;
- VS Code and WASM distributions;
- desktop bundles, sidecars, archives, and release metadata; and
- active English and Chinese documentation.

`CITATION.cff` remains canonical. Documentation may ask users to acknowledge
CatGo and cite the preferred work, but must say clearly that this is a request,
not an extra condition on the AGPL grant.

Historical AGPL releases remain unchanged. No file may claim that commercial
use requires separate permission.

## Unverified Data Exclusion

The complete directory
`server/catgo/vendor/pormake/database/` will be removed from the repository
and all build contexts.

Because the bundled reticular builder depends on that data, its implementation
and active interfaces will be removed together:

- FastAPI routes and router registration;
- CLI command and operation registration;
- MCP tool registration and generated tool schema;
- desktop/web reticular builder tab and API client; and
- workflow-skill documentation that advertises the unavailable command.

The now-unreachable vendored PORMAKE implementation will also be removed,
minimizing unused release material and making the exclusion mechanically
auditable.

MOFX-DB access is separate from the bundled builder. If retained, it must
require one explicit source from `CoREMOF 2014`, `CoREMOF 2019`, `CSD`,
`hMOF`, `IZA`, or `PCOD-syn`. Unfiltered queries and the `Tobacco` source must
be rejected. The client and server must expose the same allowlist.

The PORMAKE provenance ledger will use an `EXCLUDED` state only after the
verifier confirms that every declared database and feature path is absent
from the repository and staged release artifacts.

## Pymatgen, ASE, and xterm Handling

Pymatgen and xterm-derived portions are covered by retained MIT license
notices. Their adopted-revision caveats remain recorded as provenance facts
and must not be rewritten as exact revision claims.

The four identified ASE-derived test functions in
`extensions/rust/src/integrators.rs` will be removed. Production integrator
code is not in the mapped ASE-derived scope, so runtime behavior is
unchanged. Any replacement coverage must be newly specified from CatGo's
public numerical invariants and added test-first without copying the removed
test structure or fixtures.

The provenance ledger will distinguish:

- redistribution permission supported by an included upstream license and
  notice;
- incomplete historical revision provenance; and
- excluded derived material whose declared paths or symbols are verified
  absent.

The release verifier may accept a notice-backed open-source status and a
verifier-proven `EXCLUDED` status. It must continue to reject `BLOCKED`,
`UNKNOWN`, and `REVIEW_REQUIRED`.

## Release Pipeline

The existing hardened v1.4.6 pipeline remains:

1. every publisher verifies the exact tag and source commit;
2. all platform artifacts are built and signed;
3. required assets and SHA-256/signature receipts are verified;
4. a draft GitHub release is mirrored transactionally to Cloudflare R2;
5. `https://dl.catgo-ucsd.org/` and versioned asset paths are verified;
6. `latest.json` is written last as the automatic-update commit marker; and
7. the finalizer publishes the GitHub release only after all required
   attestations succeed.

The download page and in-app updater must use only
`https://dl.catgo-ucsd.org`. GitHub remains a release record and fallback,
not the normal download path.

No workflow may tag, publish, upload to PyPI, promote R2 roots, or make a
GitHub release public while release-rights verification is unresolved.

## Error Handling and Fail-Closed Rules

- A missing or unsupported license status fails release verification.
- An `EXCLUDED` ledger with any declared path or symbol still present fails.
- A reticular or prohibited MOFX-DB request returns a clear unavailable or
  invalid-source error; it must not fall back to an unfiltered query.
- Missing assets, signature mismatches, wrong tag/source identity, or failed
  Cloudflare verification keep the GitHub release in draft and restore the
  previous public R2 root.
- Automatic-update metadata is never advanced independently of the verified
  all-platform release.

## Verification

Implementation follows TDD for every behavior change. Required gates are:

- license-policy and legal-distribution tests prove AGPL consistency and
  remove custom noncommercial claims;
- exclusion tests fail before deletion and then prove the PORMAKE database,
  reticular entrypoints, Tobacco source, and unfiltered MOFX-DB paths are
  absent or rejected;
- provenance tests prove the four ASE-derived tests are absent and all
  retained third-party notices ship in every distribution;
- release-rights verification passes without `BLOCKED`, `UNKNOWN`, or
  `REVIEW_REQUIRED`;
- all Node, frontend, VS Code, Rust, Python, workflow, WASM, packaging, and
  Wrangler dry-run gates pass;
- the real `dump.traj` gate remains 100/100 exact and at least 24 unique
  presented FPS;
- PR CI is green, including Docker's release-rights job; and
- after release, the public download page, every platform asset,
  `latest.json`, and the app automatic updater report v1.4.6 through
  Cloudflare.

## Pull Request and Rollout

PR #548 will be updated rather than discarding its reviewed release-pipeline
work. Its title and body will describe an AGPL v1.4.6 release, the removal of
the custom license, and the temporary reticular feature exclusion.

The PR remains draft until all local and CI gates pass. It is then reviewed,
marked ready, merged, and released through the verified workflow. The
noncommercial/open-core idea may be revisited later only for new,
clearly-separated code whose copyright CatGo controls.
